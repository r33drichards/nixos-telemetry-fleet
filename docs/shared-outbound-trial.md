# Existing canary shared outbound IPv4 trial

The owner approved trying Azure's shared default outbound access first, without a paid IPv4 address, NAT gateway, load balancer or proxy. This is a connectivity experiment, not proof of reliable GitHub access. Normal bandwidth accounting still applies; the existing budget ceilings and free-instance/P6 requirements remain unchanged.

For a fresh private plan only, set `shared_default_outbound_ipv4=true` and `approval.shared_default_outbound_ipv4=true` in the existing private topology. Defaults remain false. Keep the same backend `fleet/amd-canary/terraform.tfstate` and all VM/image/key/security inputs. The saved-plan reviewer selects a separate bounded intent from those plan-bound variables: exactly one existing subnet update, false to true, with every other subnet field unchanged and seven resource no-ops. Unknown results, extra resources, creation/replacement, NSG/VM/key/custom-data changes or other updates fail closed. The initial-create contract is unchanged when the trial flag is false. No CI power-management or additional IAM permission is introduced.

Review the fresh saved plan and its hash before apply. The native operator—not GitHub Actions—handles the separately authorized stop/deallocate/start using existing human permissions. Microsoft documents that changing the subnet's private/nonprivate setting requires existing VMs to be stopped and deallocated for the change to take effect. Preserve the P6 OS disk, gallery image, static public IPv6, SSH host key and closed Comin marker; no VM rebuild.

After the controlled cycle, verify the same host key and IPv6 SSH, then test IPv4 HTTPS to GitHub with bounded timeouts and retained TLS verification. Verify IPv6 Nix-cache connectivity remains intact. Do not rely on ping: shared default outbound does not support ICMP. Do not substitute paid outbound resources if the trial fails. Comin activation and its privileged bootstrap remain separate. A rollback would need its own reviewed update plan; this enable-only contract cannot silently reverse or broaden changes.

[Microsoft default outbound documentation](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/default-outbound-access) describes the stop/deallocate requirement and the nondeterministic, platform-managed nature of shared outbound access. Its compatibility with this VM's public IPv6 must be established by the actual test.
